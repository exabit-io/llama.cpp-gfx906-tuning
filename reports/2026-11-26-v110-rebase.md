## 2. The merge (`merge-v1.1.0`)

19 files with textual conflicts, 32 hunks; the merge commit message lists each. Where his merge and ours differed, the
branch has his.

**Upstream #31669 (2026-11-24), "GDN: use replay instead of rollback".** For the delta-net models upstream removed the
snapshot branch: with `n_rs_seq > 0` a context keeps one state plus the inputs of the last ubatch and the gdn op
replays the kept tokens. The fork has the snapshot ring (one sequence) and plane-indexed snapshots (parallel contexts).
Everything is kept, one rollback per context; `llama_memory_recurrent::ring_supported()` is the ring's condition as
one static function for the memory and the context. An op with replay inputs runs on upstream's recurrent kernel (the
fork's column-thread and chunked kernels do not replay).

| Arm, `-np 4`, MTP n_max 3 (`rs-modes2.sh`) | Text, long / short request | Recurrent memory |
|---|---|---|
| replay, recurrent kernel | `4893c7466db7` / `992ec9e4d9de` | 652.8 MiB |
| snapshots, recurrent kernel | `4893c7466db7` / `992ec9e4d9de` | 2,394 MiB |
| snapshots, the fork's kernels | `6ffd45358f64` / `a84585d1e445` | 2,394 MiB |

- Replay and snapshots give the same text once both run the recurrent kernel; upstream's state-level cases pass
  (`replay` 15/15, `rollback` 16/16). The difference a first session saw is the fork's other kernels, not a fault.
- In that session (every arm at the clamped clock) replay ran prefill about 15 % and decode 2 to 3 % slower.
  **Decision: the fork keeps what it had** (ring; snapshots for the other contexts); `LLAMA_RS_REPLAY=1` gives those
  contexts upstream's replay, for a quarter of the memory. The speed ratio is to be repeated at full clock.

Merged without a textual conflict and changed: `cparams.rs_replay` is decided after the fork's `n_ubatch` clamp of
`n_rs_seq` (upstream sets it before; it would have stayed true at `n_rs_seq` 0); upstream's new free function
`build_attn_iswa_impl()` calls the fork's replica-aware cache helpers through `gctx`; the replay's conv-window input is
an input of its own, not a view; `ggml_gated_delta_net(..., K)` is not deprecated in the fork; the K > 1 gated delta
net cases upstream deleted from `test-backend-ops` are back (the ring uses that form).

Fix commits beside the merge: the top-k softmax width; `fattn.cu` returns NONE for 576/512 when the tile kernel has no
instance for the GQA ratio (**an upstream v1.1.0 abort on HIP**: stock v1.1.0 dies at `fattn-tile.cuh:1230` on the new
`hy_v4_flash` test model, the 61st of 150, taking the rest of `test-llama-context` with it); the carried MTP row.

## 4. Master (`master-v110`): the 20 Exabit commits on the merge, plus two

Ported straight onto the merge. What had to be adapted (the port notes are in the commit messages):

- terms 02, 03 (`norm.cu`): `rms_norm_f32` is a template over float and BF16 rows (#32135); `do_q8` and `do_preadd`
  are float only and instantiated only for float.
- term 04 (GDN producer fold): the kernel takes upstream's replay arguments too; the fork's fast kernels only without

## 7. Two things that broke every build before any code was touched

- `gcc-14` without `libstdc++-14-dev` (installed 2026-11-17 for a kernel-module build): both ROCm compilers pick the
  newest GCC directory and end at `'cmath' file not found`. The build and package scripts pin the HIP compiler to the
  host compiler's directory (`--gcc-install-dir`).
- The server's web UI is downloaded at build time by build number. A fork's number names no upstream build, the
  script falls back to `latest`, and a `latest` newer than the tree fails the asset check: his master does not build
  out of the box today. The scripts set `HF_UI_VERSION` to the upstream build of the merged release (b12774).

## 8. Clock clamp at 19:43 UTC

All four dies latched at sclk 1000 MHz 24 minutes after the boot and stayed there (88 to 92 W per die under full
load, below the cap; perf level high ignored). It came within seconds of a 56-thread build starting while a GPU test
ended; total DC peaked at 768 W and no SMC envelope was exceeded in the 5-second samples, so the cause is not
established. It was noticed two hours later, when the fold check's watchdog fired; the suite's watchdog had not fired
on its 3-minute perplexity step, and only result lines had been read.

- Valid: every pass/fail, perplexity, text and draft count of the evening.
- Void: every tok/s after 19:43. `mtp-depth-v110.sh` was stopped by its watchdog in its first cell.
- Kept from now on: no builds while the dies are loaded, also during correctness runs; after every GPU job the
  watchdog's clock column is read, not only the result lines.

## 10. Direction (2026-11-26): the fork is its own project

None of the merges offered to mxxm-t was taken (PRs #17, #22, #23, #24; #25 is open). From here on the fork follows
upstream llama.cpp releases itself and pulls in the code that serves its goals. His gfx906 patches stay, and his later
changes keep being read and taken on their merit. What ends is being bound to his tree: a cycle does not wait on it,
a resolution is not chosen only to stay mergeable for him, and no merge is offered as a pull request unless the lead
asks for one. The condition named for this: following upstream must carry no major, statistically significant
performance penalty against his fork.

That condition has no measurement yet (the last comparison of this kind is September's, on stock b10288), so one is
set up, to run at full clock (`tools/release/v110/substrate-v110.sh`; its header holds the reading rule, written
before the first run):

| | |
|---|---|
| Arms | his master `557a6068f` (b12500); the merge `a3aa1c772` (the same patches on upstream v1.1.0); our master `9a7177d0a`. Same compiler (ROCm 10.0), runtime and environment; RCCL on in every build (`sub-build.sh`). Upstream alone is an optional arm, not a candidate |
| Cells | Qwen3.8-27B Q8_0, four dies, `-sm tensor`, f16 KV: 4 x 65536 and 1 x 260864 (the design points), 8 x 4096, 16 x 2048 (`llama-batched-bench`), and one MTP stream on a 47K-token prompt (`sub-mtp.sh`) |
| Design | 5 blocks per cell, every block runs every arm once in a fresh random order |
| Statistic | samples paired by block, mean of ln(a/b), Student's t, 95 % interval, Holm's correction over the rows of a pair (`sub-stats.py`) |
| Words | significant = adjusted p < 0.05; major = significant and the whole interval beyond 2 % (the acceptance floor of every package so far; `LINE=` reads the data against another line) |
| Read on | the merge against his master (following upstream's releases, nothing else changed) and our master against his master (what we ship against his fork) |

The statistics script was checked on synthetic data with known effects (it returned them); the session has not run.
