# 2026-10-22: llama.cpp v0.7.0 on gfx906 - reconcile with mxxm-t, rebase, PR #22, packages

**What happened.** mxxm-t closed our v0.5.0 PR (#17) on 2026-10-13 after merging upstream b11553 into his fork himself.
The 18 Exabit commits of `master` were moved onto his master (`c4d12e2c0`), and v0.7.0 (`620d222`, b11669) was merged
into his master as `merge-v0.7.0`, offered as [mxxm-t/mx-llama.cpp#22](https://github.com/mxxm-t/mx-llama.cpp/pull/22).
The Exabit commits were then rebased onto it (`master` = `ef70ef51e`). Both the build and PyTorch 2.14.1 were packaged,
signed and published. Procedure: `RELEASE-RUNBOOK.md`. Raw logs: `data/raw/2026-10-22/`.

All runs: macpro2019-01, 4x gfx906 (2x Radeon Pro Vega II Duo), kernel 7.0.0-38, **ROCm 10.0.0-gfx906+20261018172427**
(installed 2026-10-22 01:54 UTC, before this work; HIP 7.15.26333, rocBLAS 5.6), GPUs pinned at 125 W by macpro-fand,
`NCCL_TOPO_FILE=/root/rccl_topo_fixed.xml`, `HSA_FORCE_FINE_GRAIN_PCIE=1`. Model Qwen3.8-27B Q8_0 unless stated. The 16K
and 2K depths below are correctness smoke values (REQUIREMENTS R2.2: nothing below 64K is a result); they compare builds
only with each other.

## 2. Silent breaks found (clean apply, wrong code)

| Where | What | Fix |
|---|---|---|
| term 04 on mxxm-t's b11553 master | upstream's GDN kernel now gives each warp 4 column segments of `lanes_per_col` lanes, each holding the whole head vector; the folded q/k L2 norm reduced over the whole warp (4x the sum of squares) | `warp_reduce_sum<lanes_per_col>` |
| term 10 | its bit-exact sum of squares assumed one column per 64-lane warp | redone for 16-lane segments, matching the generic (offset 16 first) or GCN DPP (offset 1 first) reduction order |
| term 04 (old latent) | the chunked GDN kernel ignores the folded producers; reachable for KDA (chunk 16) at 32-64 tokens | folded calls stay on the recurrent kernel |
| v0.7.0 merge | upstream's MMA chunked GDN kernel (#29353) writes only the final state | skipped when the snapshot ring keeps K > 1 (gfx906 never takes it: HIP enables it on RDNA3.5 only) |
| v0.7.0 + term 04 | the MMA kernel reads graph q/k/g/beta that a folded call has not computed (both engage at exactly 64 tokens on NVIDIA) | skipped when the fold is active |
| v0.7.0 merge | LiliCorr (#30506) stores the projected rows of each inject only in the eager DFlash path; the fork's deferred prompt encode replays injects without it | a LiliCorr drafter stays on the eager path |

## 3. The decode-path folds after the port

Perplexity, Qwen3.8-27B Q8_0, wikitext-2, 2K x 8 chunks, ubatch 16 (every fold engages: norm+Q8_1 needs <= 16 rows, add+norm
and the GDN producer fold <= 64), `-sm tensor`. +/- is llama-perplexity's standard error (0.13 throughout). Each arm ran once;
two arms repeated (`folds-on2`) gave identical values, so the path is deterministic run to run.

| Arm | old master `82868aa3b` | reconciled (b11553 base) `19f47c4d0` | rebased master `ef70ef51e` |
|---|---|---|---|
| all folds on (default) | 5.0813 | 5.0677 | 5.0677 |
| norm+Q8_1 fold off | 5.0813 | - | 5.0677 |
| add+norm fold off | 5.0813 | - | 5.0677 |
| GDN producer fold off | 5.0767 | - | 5.0568 |
| GDN fold: only the q/k L2 norm on | 5.0813 | - | 5.0677 |
| all folds off | 5.0767 | 5.0568 | 5.0568 |

Only the folded q/k L2 norm changes any value; the norm+Q8_1, add+norm, sigmoid and gate folds are bit-exact. Its effect,
as KL divergence of folds-on against all-folds-off logits (2K x 4 chunks, ubatch 16):

| | old master | rebased master |
|---|---|---|
| mean KLD | 4.24e-4 +/- 1.7e-5 | 3.87e-4 +/- 1.8e-5 |
| 99.9th percentile KLD | 0.0110 | 0.0084 |
| maximum KLD | 0.0399 | 0.0609 |
| same top token | 99.389 +/- 0.122% | 98.974 +/- 0.158% |
| mean change of the top probability | -0.015 +/- 0.009% | +0.022 +/- 0.010% |
| RMS change of the top probability | 0.603 +/- 0.041% | 0.611 +/- 0.049% |

Same magnitude, no systematic bias: the port is numerically equivalent to the original fold.
