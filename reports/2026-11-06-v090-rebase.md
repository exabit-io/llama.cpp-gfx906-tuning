# 2026-11-06: llama.cpp v0.9.0 on gfx906 - merge, PR #23, rebase, package, generated RCCL topology

**What happened.** PR #22 (v0.7.0) was never merged. llama.cpp v0.9.0 (`cd959ba`, b12110; 557 upstream commits past
mxxm-t's b11553 master) was merged into mxxm-t's master and offered as
[mxxm-t/mx-llama.cpp#23](https://github.com/mxxm-t/mx-llama.cpp/pull/23), with a separate HIP fix for an upstream bug.

were rebased (`gfx906/v0.9.0/r0/master` = `58db0123a`), packaged and published. A stale RCCL topology file was found and
replaced by a generator. Procedure: `RELEASE-RUNBOOK.md`.

All runs: macpro2019-01, 4x gfx906, kernel 7.0.0-42 +barfix4, ROCm 10.0.0-gfx906+20261018172427, GPUs at 125 W by
macpro-fand. Model Qwen3.8-27B Q8_0 unless stated. 16K and 2K depths are correctness smoke values (R2.2), comparable build to

## 4. RCCL topology

The second module's PCI numbers moved with the 2026-10-23 card install (GPUs 1b/1e -> 19/1c). `/root/rccl_topo_fixed.xml`
still named the old addresses, so `ncclCommInitAll` failed ("internal error") and every RCCL build fell back to the internal
all-reduce silently. Replaced by `rccl-topology.service` (source `tools/rccl-topology/`): it derives the physical ring from
sysfs at every boot into `/var/cache/rccl/topology.xml`; `/etc/rccl.conf` points RCCL at it; 179 scripts no longer set
`NCCL_TOPO_FILE`. rccl-tests all_reduce_perf, 1 GiB, four GPUs, busbw (out-of-place / in-place):

|---|---|
| generated (via /etc/rccl.conf) | 34.07 / 33.92 |
| firmware's links | 24.80 / 24.81 |
| none (RCCL's own detection) | 24.62 / 24.60 |
| hand-made file, 2026-09-04 | 33.49 / 33.67 |
